# 低功耗與多資料夾實作說明

2026-09-17：服務 2026.09.17.1，設定 v4，MCP 契約 v3，九個唯讀工具維持不變。

## 整合決策

資料夾規格原要求維持 v3；本次同時新增 power 設定，因此採電源規格的 v4。v1/v2/v3 採 off 遷移；v0 仍須確認。GUI 清單第一筆衍生 root/default_root，既有 ID、名稱及個別排除保留，新資料夾配置隨機 ID；改路徑保留 ID 與排除。

## 電源架構

- power_windows.py：明確 Win32 signature、EcoQoS、SystemRequired、scheme API、可取消 native wait、模式廣播。
- power_policy.py：驗證、序列化 mode transition、生命週期 request、scheme transaction、journal 與 guard client。
- power_restore_guard.py：独立於 Connection Job，僅接收固定 mode 指令，以阻塞 pipe read 等待。GUI 結束會關閉唯一寫入端；EOF 觸發回復，不使用定時輪詢。也處理正常關閉指令。
- 系統匣 WNDPROC 只發 Python event；橋接執行緒透過 Tcl thread queue 通知 GUI，避免從 ctypes callback 重入 Tk。
- Connection 等待程序或取消 handle；三階段均事件等待，init/doctor 保留 deadline，run 無固定 50 ms wake。
- MCP 透過一般命令參數取得隨機模式通道名與 owner PID；三個 manual-reset events 向所有存活 MCP 子程序廣播。極致模式才對 MCP 自身啟用 EcoQoS，切回 LOW/OFF 還原系统管理。owner 終止時也還原。

## 策略

| 項目 | LOW | EXTREME |
| --- | --- | --- |
| GUI EcoQoS | 啟用 | 啟用 |
| MCP EcoQoS | 系統管理 | 啟用 |
| Tunnel QoS / Job cap | 不套用 | 不套用 |
| Sleep AC/DC | 0 / 0 | 0 / 0 |
| EPP AC/DC | 70 / 85 | 90 / 100 |
| CPU max AC/DC | 100 / 100 | 80 / 60 |
| Boost | 3，支援時 | 0，支援時 |
| 顯示器逾時 | 沿用 | 最多 300 / 120 秒，原值更短則保留 |

SystemRequired 由實際 Connection 生命週期取得及釋放，永不建立 DisplayRequired。request 失敗時不宣稱保持喚醒成功；QoS/選配 CPU 設定不可用時保留警告。manage_power_scheme=false 可供部署取消整機方案，但僅剩 Power Request 時不保證 Modern Standby DC 不休眠。restore_original_plan/keep_system_awake=false 為不支援的安全停用選項，驗證拒絕。

advanced_job_cpu_cap_percent 接受 null 或 10–100 整數，僅保留設定與 API 能力；非 null 會提示 POWER_CPU_CAP_NOT_APPLIED。Connection Job 邊界尚含 Tunnel，不套用硬上限。timer resolution ignore 屬選配，本版未啟用。

## 回復與交易

還原程序持有每設定路徑唯一 mutex，拒絕重複 guard。複製方案後先原子保存 journal，再修改並啟用候選方案。LOW↔EXTREME 以新副本取代，失敗回復先前方案。舊副本刪除失敗會保留於 journal 供再次清理。

journal 位於本機設定目錄，只包含 guard PID、程序建立時間（防 PID 重用）、original GUID、owned GUID 清單與 mode；不混入一般設定备份。與原規格單一 temporary GUID 不同，是為涵蓋模式轉換中可能同時存在的兩份方案。

關閉先切回 original，再刪除所有 owned 方案；若使用者手動改選其他方案，保留使用者選擇。回復失敗不刪 journal。Guard 自身被強制結束時，下次啟動核對舊程序身分後恢復；不能保證 guard 也同時被殺死時立即回復。損毀 journal 不猜測 GUID、不自動刪除未知方案。

## 驗證與限制

一般回歸使用假電源 API，僅 native wait 測試建立暫存睡眠子程序。正式設定、通道、排程、金鑰與整機電源均不變更。

固定 benchmark 案例使用 shared/README.md；可先執行 OFF baseline：

```powershell
.\.venv\Scripts\python.exe -B benchmark_e2e.py --mode local --root shared --cases benchmark-power-cases.json --output engineering-power-off-local.json
.\.venv\Scripts\python.exe -B benchmark_e2e.py --mode stdio --root shared --cases benchmark-power-cases.json --output engineering-power-off-stdio.json
```

以下會暫時改動整機電源，僅在同意實機測試後使用：

```powershell
$env:MCP_LOCAL_ALLOW_POWER_INTEGRATION_TEST = '1'
.\.venv\Scripts\python.exe -B benchmark_power.py --allow-system-power-changes --mode stdio --root shared --output-dir reports/power-integration
```

每模式按固定 OFF/LOW/EXTREME 順序、每案例 100 次。工具輸出時間統計，不輸出原始檔案內容；三態 benchmark 不代替 AC/DC、Modern Standby、螢幕關閉、斷網重連、8/24 小時遠端 soak 或 WPR/WPA。未完成這些實機驗收前，不宣稱功耗下降比例或符合全部性能門檻。

Windows API 依據：[Process Power Throttling](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-process_power_throttling_state)、[Quality of Service](https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service)、[Power scheme management](https://learn.microsoft.com/en-us/windows/win32/power/managing-power-schemes)。
