# MCP-Local Security Center

安全中心是既有三模式之外的獨立安全控制層，並非第四種權限模式。唯一桌面仍為 .NET 10 WPF Fluent Theme；本機操作經既有私有 stdin/stdout Python 管線。公開 MCP 維持唯讀 22、開發控制 34、主機控制 36 個工具，沒有授權、延長、撤銷政策或稽核管理的遠端工具。

## 模組與生效路徑

| 模組 | 有效責任 |
| --- | --- |
| `mcp_local/policy.py` | 獨立 v1 政策、嚴格型別與依賴驗證、樂觀版本衝突、同目錄暫存與原子替換 |
| `mcp_local/host_authorization.py` | 僅記憶體的 monotonic 限時授權；不持久化、重開或重連不延續 |
| `mcp_local/local_channel.py` | Windows Local 命名共享記憶體、Ed25519 政策與授權簽章、HMAC 執行層回報、有界框架及心跳 |
| `mcp_local/sensitive_detector.py` | 內建敏感規則、固定文字規則、風險分類及有界偵測 |
| `mcp_local/response_guard.py` | MCP 最終送出 stream 的文字、結構化結果、錯誤及通知檢查；遮罩或拒絕無法檢查的內容 |
| `mcp_local/security_audit.py` | 固定 metadata 事件、SHA-256 鏈、篩選、詳情、匯出與版本確認清除 |
| `mcp_local/security_center.py` | 桌面 authority、執行層消費者、Session enforcement、即時確認及故障鎖定 |
| `desktop/wpf/SecurityCenterView.cs` | 第六頁安全中心分為總覽、設定與安全事件；草稿、保存版本、實際確認及錯誤分開呈現，快捷授權受已儲存上限限制 |

啟動入口 `mcp_local.local_files_mcp.main` 安裝執行層與最後回傳防護。主機 `HostProcess` 在 resume 前再次驗證授權；互動輸入在入口及實際寫入前驗證。既有 Job、未提升 token 檢查、檔案 API 保護與 VM 隔離保持有效。

政策檔為既有受保護狀態目錄下的 `security-policy.json`，事件檔為 `security-audit.jsonl`。它們與連線設定 v8 分開；工具契約 13 不變。未存在政策檔的舊安裝只載入關閉預設值，不自動寫檔或啟用。未知版本、損毀、既有檔案遺失及外部修改不得當作預設關閉。第一次明確保存才建立獨立政策；異常原檔保留。

## 本機 authority 與通訊

桌面 Python 每次啟動產生新的 Ed25519 私鑰、公鑰、隨機映射識別與回報 HMAC 金鑰。私鑰不傳入 MCP、Tunnel、命令環境或持久化設定。連線生命週期只將公鑰及暫時映射能力交給本次子程序；MCP 啟動後移除環境描述。HostProcess 原有環境白名單不轉送這些能力。

共享記憶體不建立磁碟 mailbox、背景服務、TCP 或 HTTP 端點，不變更 Windows ACL。九個 64 KiB slot 包含一個本機簽章控制快照及最多八個執行層回報。共享 mutex 保護完整框架；命名物件沿用 Windows 目前使用者權限。MCP 消費者只有驗章公鑰，不能透過此協定簽發授權。這些機制不抵禦同 Windows 帳戶的惡意程式讀取程序記憶體或修改來源；不宣稱為憑證沙箱。

桌面心跳約 250 ms，執行層檢查約 100 ms；簽章快照有效期 3 秒。每次命令啟動／互動輸入／回傳前再次驗證。鎖定、框架損毀、過期、簽章不符、authority 異常、事件寫入或回報失敗都不能視為健康。通訊失效鎖定至本機「安全恢復」發出新 recovery generation；恢復不授權。UI 以政策摘要及 lease generation 的執行層回報確認，而非只以「送出成功」推論生效。沒有執行層時顯示尚無受管理用戶端。

尚未啟用政策的執行層不因通訊診斷失敗而改寫既有工具回傳或阻擋既有命令。曾收到啟用政策後，未確認的停用或通訊故障不能清除防護；必須收到健康、已簽章的本機政策。外部政策內容變更不能藉「恢復」直接取代已確認政策，需先還原原政策。政策啟停操作均由本機 UI 確認。

## 主機授權與 Session

安全政策及主機授權保護同時啟用後，僅本機 WPF 明確確認可簽發 1 至 60 分鐘、且不超過已儲存上限的授權。私有桌面命令不能從 MCP 呼叫。保存政策、重連、停止連線、關閉桌面及恢復都撤銷原授權。

| 情境 | 新命令與互動輸入 | 已啟動主機 Session |
| --- | --- | --- |
| 授權有效、政策與通訊已確認 | 依既有模式及工具規則執行 | 保持原 Job、lifetime 與資源上限 |
| 到期或立即撤銷；terminate 策略 | 拒絕 | 終止本次 Session Job，回報停止是否確認 |
| 到期或立即撤銷；finish 策略 | 拒絕 | 僅保留到原 lifetime；不得新增互動輸入 |
| 通訊、政策或稽核狀態無法確認 | 拒絕 | 終止主機 Session；失敗維持鎖定與未確認狀態 |

讀取已完成輸出、列出 Session、關閉與終止自己 Session 不要求新的授權。主機檔案 API 仍使用既有保護模型；授權保護不把主機命令變成 allowlist 或沙箱。PowerShell、Python、Git、建置工具仍由原主機模式執行；VM 模式不改為主機 fallback。

直接 STDIO／CLI 仍讀取相同獨立政策。安全政策關閉時維持既有行為；啟用主機授權後，沒有本機 authority 的 standalone 主機命令會拒絕。需要限時主機命令時使用 WPF 管理的連線；CLI 沒有自動核准、秘密免驗證參數或遠端核准替代路徑。

## 真正送出的回傳

防護位於 SDK `SessionMessage` 送出邊界，檢查 `result`、協定 error 的 message/data 及通知 params。FastMCP 文字 JSON 與 `structuredContent` 兩份內容都檢查；保留協定 ID 與錯誤碼。內建 private key、常見 API token、Bearer、密碼指派與 email 規則可逐條啟停及分類；新增規則只接受固定文字，避免執行任意正規表示式。

遮罩保留文字長度，避免 Session 分頁 offset 因遮罩位移；結構化敏感值可使用固定遮罩字串。block 策略回傳固定 MCP 錯誤，不附原值。圖片、音訊、blob、resource link、base64／hex binary、未知值、超過 4 MiB 字元、50,000 節點、32 層或規則比對上限均阻擋，不標示已安全檢查。

Session 輸出可能分段完成 token，因此啟用回傳防護時不直接送出仍執行中的片段。程序結束後先檢查完整保留 buffer，再按原 offset 分頁；buffer 已溢位則阻擋，不以殘片宣稱安全。UI 顯示輸出暫存狀態；長跑程式仍可輸入，但輸出需等結束後檢視。這是啟用時明確告知的行為改變。

規則比對不保證找出所有敏感資訊，亦不解碼任意自訂編碼、跨獨立請求拼接或理解影像內容。僅保護經此 MCP 送出的結果，不攔截受信任命令自行存檔、剪貼簿、另行網路連線或其他程式輸出，不能稱為完整網路防外洩。

## 事件、原始監控與恢復

事件只接受固定 kind、風險、UTC 時間、隨機 ID 與計數；不接收請求原文、命令、路徑、偵測命中原值或任意例外。清除事件包含被清除鏈的 prior head，便於與先前匯出核對。事件鏈能發現不一致，但不是對同帳戶攻擊的不可否認證據。

原始請求監控保留原輸入與必要的截斷／遺失提示，不因安全事件遮罩而改寫請求證據。監控安裝順序使回應觀察到經 guard 處理的送出內容；原始輸入仍可能包含敏感資訊，介面提示須保留。安全事件清除不影響原始監控。

本機事件檔上限 4 MiB；達上限或完整性失敗時拒絕靜默丟棄。執行層的待確認事件佇列有界，回報會明示遺失計數。狀態異常先檢視診斷；通訊可恢復時按「安全恢復」，仍須重新本機授權。政策或事件檔損毀時保留原檔，需由本機操作者還原有效檔案後恢復；UI 不把損毀當成關閉預設。清除需要最新事件 revision、正確確認文字及本機確認；匯出保留完整鏈。

## 驗證邊界

`tests/test_security_center.py` 使用合成政策與暫存目錄，覆蓋版本／衝突、單調時限、簽章竄改、過期、故障鎖定／恢復、Session 完整 buffer、真正 STDIO 的三模式契約、回傳防護與主機 Job 撤銷。
`desktop/wpf/SecurityChecks.cs` 僅在隔離 fixture 下操作真實 WPF 控制項及私有 Python 管線；通訊 peer 為合成替身，不能代替正式 Tunnel、VM 或人工授權驗收。測試與報告應分開列示各類證據。
